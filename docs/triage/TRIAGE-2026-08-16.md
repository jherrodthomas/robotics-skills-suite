## Known defect in the staleness rule

The 30-day quiet rule keys on GitHub `updated_at`. Autonomous label edits and auto-comments both
bump `updated_at`, so this task resets its own staleness clock every time it touches an issue.
Issues #38–#41 were opened 2026-07-20 and have had no human activity in 27 days, but their
`updated_at` reads 2026-08-02 purely because the 2026-08-02 triage run commented on them. Under
the current rule they will never age past 30 days as long as triage keeps visiting them.

Recommended fix (needs a human decision, not applied): measure staleness from the most recent
event **not** authored by the autonomous account, or fall back to `created_at`.
