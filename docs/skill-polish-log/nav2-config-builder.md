Nav2 consumes the frame vocabulary those two settled, and taking it five days after `tf-tree-spec` means the frame contract is transcribed once rather than reconciled twice.

**What's good**
- Frontmatter valid in both halves: `name` present, matching filename and internal zip directory; `description` present and well inside 1024 chars.
- The pair was already in lockstep — the reviewer's eight review areas mapped cleanly onto the builder's eleven tabs, so nothing had to be re-aligned before adding content.
- The tab spine was right and was kept, then extended: global costmap → local costmap → inflation → planner → controller → recovery → localization → validation is the order a Nav2 configuration is actually filled in.
- Unlike `eoat-spec` (2026-08-26) and like `tf-tree-spec` (2026-08-27), the builder did name a version baseline rather than omitting one. The defect was that the baseline was **wrong**, which is a different and worse failure than silence — see finding 1.

**What to fix**
1. **`per ROS 2 Humble or Iron Nav2` — a dead distro in the description, and the highest-severity finding here.** **Iron Irwini reached end-of-life in November 2024**, twenty-two months before this run. The builder was not merely stale, it was directing users at an unsupported distro, and the reviewer would have validated a configuration built against it because the reviewer pinned nothing at all (`per ROS 2 Nav2 best practices`). This is the first time in this repo's polish history that a builder's stated baseline was *wrong* rather than *absent*, and it is the reason the mandatory edition check is worth running even on the domains where it does not formally fire — **ros2 is not in the safety-critical set, so the check was run voluntarily and this is what it found.**
2. **No inheritance contract with the two upstream workbooks it depends on.** `tf-tree-spec` (#52) states explicitly that `nav2-config-builder` consumes `global_frame`, `robot_base_frame` and `odom_frame` from it, and `urdf-model-spec` (#49) states that Nav2's footprint and inflation derive from its *collision* geometry. Neither statement had a counterpart on this side. The chain was documented in one direction only, which is the same as not being documented.
3. **`inflation parameters` named without the mechanism.** No inscribed radius, no circumscribed radius, no cost constants, and no statement that `cost_scaling_factor` is a **decay rate that runs backwards from intuition** — larger values give a *tighter* gradient. A user raising it to get more clearance gets less, silently, and both halves were blind to it.
4. **`global and local costmap configuration` as a single undifferentiated phrase.** The single most consequential difference between the two costmaps — the **local costmap's `global_frame` is `odom`, not `map`** — was absent. So was the inflation-layer-last ordering rule and the static-layer-in-global-only rule.
5. **`behavior tree configuration` claimed as a tab, colliding with `behavior-tree-spec-builder`.** The repo has a dedicated pair for BT design. Two skills owning tree structure guarantees divergence; the boundary was undrawn in both directions.
6. **`recovery behaviors` listed with no server name.** The recovery server was renamed `recoveries_server` → **`behavior_server` in Humble**. A workbook using the old name configures nothing. Neither half named either.
7. **`AMCL or SLAM Toolbox setup` with the "or" unexplained.** Both publish `map` → `odom`. Running both violates the single-parent invariant `tf-tree-spec` had just spent a section establishing, in the one place a Nav2 bringup makes it easy to do by accident. This is the strongest cross-skill finding available in the ros2 domain and neither half could raise it.
8. **Plugin selection with no selection criterion.** "Controller and planner plugin selection" named no plugins and, more importantly, no *deciding property*. The deciding property is the drive type: an Ackermann robot on `NavfnPlanner` is handed paths it cannot execute.
9. **No lifecycle or bringup ordering**, despite it being on the tab list. A Nav2 node absent from every `nav2_lifecycle_manager` `node_names` list never activates — the process runs, the parameters load, nothing happens. It is the quietest failure in a Nav2 bringup and a paper reviewer is the only thing that catches it.
10. **Goal checker and progress checker absent entirely.** Without a progress checker the recovery behaviours the builder does list can never fire. The builder specified behaviours and omitted their trigger.

**Verification performed (ros2 is not a mandatory-check domain; run anyway)**
- **ROS 2 Lyrical Luth confirmed against ros2_documentation and docs.ros.org**: twelfth ROS 2 release, May 2026, **LTS supported to May 2031**, Ubuntu 26.04 among supported platforms. Matches what #49 set on `urdf-model-spec`; the distro table is inherited from that skill rather than re-derived, per the same rule `tf-tree-spec` follows.
- **`cmd_vel` TwistStamped migration confirmed against the Nav2 Jazzy→Kilted migration guide and the upstream notice**: `enable_stamped_cmd_vel` defaults **false in Jazzy and older**, and **Kilted and newer default to `TwistStamped`**. This is a genuine cross-distro behavioural divergence, not a rename, and it presents as a robot that plans normally and never moves. Recorded as the highest-yield single check in the reviewer.
- **Nav2 Lyrical release confirmed (announcement dated 2026-08-25, seven days before this run)**: `nav2_ros_common`, plugins moved to `nav2::LifecycleNode`, subscription argument reorder with QoS optional and last, `inscribed_obstacle_cost_value` (default 99) fixing the 253→99→251 static-layer round-trip, MPPI additions, adaptive goal checker, collision-monitor toggles and exclusion zones, per-distro documentation versioning.
- **One claim deliberately not asserted.** The Lyrical announcement describes "an symmetric inflation layer to incentivize left- or right-hand side passing". The wording is internally inconsistent — a left/right-hand bias requires an *a*symmetric inflation — and the Kilted→Lyrical migration page could not be retrieved (the fetch tool restricts to URLs surfaced by search, and only the Kilted *source* page was returned). Rather than guess, the builder records the feature as directional inflation **with an explicit instruction to verify the parameter name against the migration guide before recording it**, and this ambiguity is carried as a follow-up. Recording a plausible-sounding parameter name would have been the `iso3691-4` failure mode from W35 in reverse.
